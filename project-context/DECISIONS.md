# Decisions and traps
Updated: 2026-10-27

| ID | Decision or pitfall | Why / evidence | Revisit when |
| --- | --- | --- | --- |
| D-001 | **Native Qt (PySide6) app, single process, no HTTP/WebSocket server** | User rejected the browser UI twice ("要做成exe的", "不是网页版的，是用 python 图形用户界面做"); also removes port-permission trouble | a headless/remote mode is requested |
| D-002 | **Deliver from source only; no `.exe`** | Corporate policy blocks running self-built executables — the built exe fails with "拒绝访问" (L-006) | policy changes, or IT signs the binary |
| D-003 | `QPlainTextEdit` with `setMaximumBlockCount` for the log | Appending 10k+ lines/s through per-row widgets stalls the GUI thread; a text document is O(1) per append | rows must be individually interactive |
| D-004 | Pause buffers **raw chunks**, never parsed lines | Resume must replay exactly what arrived, including a partial line (R-012, R-017) | memory cap hit (capped at 64 MB, counted, surfaced) |
| D-005 | Formatting (hex / escapes / timestamps) happens at render time | The stored bytes stay pristine, so toggles are reversible without re-reading the port (R-015) | never |
| D-006 | `PortManager` owns the port on a reader thread; Qt signals carry data across threads | Emitting a signal is thread-safe; touching widgets from the reader thread is not | never |
| D-007 | Protocol engines are transport-agnostic (`Link` interface) | Enables the in-memory duplex harness → `python tools/protocol_selftest.py` proves sender/receiver symmetry without hardware; `DEMO` port enables GUI tests | real lrzsz interop test exists |
| D-008 | `DEMO` virtual serial device (`--demo`) | Lets the whole UI (AT echo, telemetry, pause, search, timers) be verified with zero hardware, and gives the user something to demo | real hardware always attached |
| D-009 | Per-line timestamp = chunk ts + baud interpolation | MS precision is required (R-010) but one chunk can carry many lines; interpolation keeps ordering sane | hardware timestamps available |
| D-010 | ~~DWM acrylic backdrop~~ → **flat solid colour** | R-020 forbids grid/blobs and asks for 纯色; a painted flat fill is also cheaper than a blur behind a full-window repaint. `theme.enable_windows_glass` is kept but unused | user asks for translucency again |
| D-011 | Recording writes to `<data>/logs`, commands to `<data>/commands.json` | Both survive app restarts and are easy to find; no registry, no admin rights | user wants per-port profiles |
| D-012 | **CLI stdout is one JSON document; humans live on stderr** | An agent must be able to `json.loads(stdout)` unconditionally, including on failure (R-022). Progress/hints on stderr keep that invariant | an interactive shell front-end is added |
| D-013 | CLI reuses `PortManager` / `run_transfer`, not a second implementation | One code path means a CLI-found bug is a GUI bug (and vice versa); `--port DEMO` gives the agent a hardware-free target (R-023) | never |
| D-014 | `omnicom/selftest.py` owns the protocol loopback | CLI, GUI and the old `tools/protocol_selftest.py` all run the same proof; no duplicated expectations | never |
| D-015 | **Light theme tokens only; no widget hardcodes a colour** | User asked for a white theme. Flipping the palette must not require hunting `rgba(255,255,255,x)` through widgets, so `theme.py` owns every token and `tools/contrast_audit.py` fails the build when a pair drops under 4.5:1 (L-022) | a dark mode toggle is requested |
| D-016 | Title-bar controls are **painted** (`GlyphButton`), not text glyphs | A 28px `QPushButton` with `padding: 7px 13px` has 2px of content box, so the label was elided to nothing — that is why `—  ❐  ✕` looked "gone" while the buttons were still clickable. Painting two lines is font- and size-independent (L-023) | never |
| D-017 | `ToggleSwitch` **accepts** its mouse events | `QWidget` ignores mouse events by default, so the release propagated to `SwitchRow`, which toggled the state straight back — clicking the knob did nothing while clicking the label worked (L-024) | never |
| D-018 | Log prefix is `[HH:mm:ss.mmm]发→◇` / `[HH:mm:ss.mmm]收←◇` | User asked for this exact shape; direction words read faster than RX/TX in a long scroll and the fixed-width prefix keeps payloads aligned (R-024) | user wants a hex-only or minimal mode |
| D-019 | **Auto-scroll = unconditional follow; the pause buffer is gone** | The user withdrew pause and reported that scrolling up killed following. Following is now unconditional while the switch is on; the floating pill is the way back when it is off. Dropping the backlog also removes the only code path that could drop bytes (L-028) | someone asks for a scroll-lock that pauses following |
| D-020 | Drop-downs are **`widgets.Combo`**, never a bare `QComboBox` | The platform arrow ignored our palette and looked alien; an editable combo did not open on click. `Combo` paints its own chevron and opens the list on a click into the line edit, while typing still works (L-029) | Qt ships a native way to style the arrow |
| D-021 | Use **`theme.mono_font()`** and also pin `font-family` in the widget stylesheet | `setFont()` alone loses to the global `*` selector in `app_stylesheet()`, so the log rendered in the proportional UI face while `font()` still reported the mono family. Pinning the family in the widget QSS is what actually took effect (L-032) | the global selector is restructured |
| D-022 | **Revised by R-049:** command/actions share one primary line; nonempty notes appear below in smaller text | User explicitly restored visible notes after tooltip-only layout; rows are 40 px without notes, 60 px with notes. Compact painted controls remain aligned | user changes the density requirement |
| D-023 | All button/icon metrics live in `theme` (`CTRL_H`, `ICON_SM`, `ICON_MD`, `ICON_SIZE`, `RADIUS`, `FONT_PX`) | The user described the controls as 乱糟糟 because every widget picked its own height and font size. One QSS block now sets `min-height` + `padding`, and the icon buttons are square with `padding: 0` (L-033) | never |
| D-024 | Search results are a `QListWidget` of `line-number  text`, each item carrying its document block | A text blob cannot be clicked; storing the block index makes double-click → `LogView.goto_block()` exact even while the log keeps growing | a real virtualised model is needed for 100k+ hits |
| D-025 | Terminal page is a **separate stack page**, not a toggle on the log | Log formatting (prefix, escapes, hex rows) is the opposite of terminal behaviour. Splitting them lets each stay honest: the log reformats, the terminal emulates (L-031) | never |
| D-026 | Command selection updates in place, animates only its row for 150 ms, and debounces persistence for 250 ms; close flushes | Rebuilds destroy animation targets; synchronous Windows replacement stalls interaction. GUI verifies identity, endpoints and persisted state (L-059) | another observer needs selection notifications |
| D-027 | Build commands even in collapsed groups; use one indented body per group and toggle only that body | Skipping collapsed rows during rebuild made them impossible to expand after group creation. Per-row visibility incurred repeated layout work; group/body/header indexes avoid scans (L-065/L-067) | list needs a virtual model |
| D-028 | RX batches use a document edit block and update overflow UI once after the batch | Scroll coalescing alone left per-insert layouts and repeated label changes on the GUI thread. Same-load stress test reduced 100-line batches from ~54 to ~20 ms without dropping lines | higher-rate hardware workloads exceed the frame budget |
| D-029 | GUI serial lifecycle/options run in one SerialBridge worker; busy gates clicks. PortManager serializes handle publication/retirement and validates request generation + failing handle identity | Direct serial calls/read-thread joins froze GUI; cancelled construction and stale errors could publish/close the wrong connection (R-055/L-069). CLI keeps synchronous API | lifecycle API is redesigned with equivalent race tests |
| D-030 | Launcher process enumeration runs on one background scan; a Qt signal updates tiles | Four-second tasklist polling blocked the GUI for ~550 ms even while serial callbacks took <1 ms. Heartbeat test spans refresh cycles and captures stalled stacks (L-070/L-073) | native nonblocking process notifications replace polling |
| D-031 | Group names use trimmed exact-match uniqueness at the store boundary; imports merge, existing saved data stays intact | Creation/rename must not mutate on rejection or bypass checks via whitespace; unchanged own names remain valid (R-056/L-071) | user requests case-insensitive names or explicit legacy migration |
| D-032 | `widgets.Button` adds motion by painting, never by resizing; animations run only while an interaction is in flight | Stiff buttons came from instant QSS state swaps (L-074). A painter-only transform keeps layout, hit area and screenshots stable, and handlers reset on disable/hide so nothing animates at rest (R-058) | a real window-scoped animation system is needed |
| D-033 | Launcher shortcuts carry stable ids; menu actions resolve the target by id | Qt signals pass dictionary copies, so `is`-based lookup matched nothing and "delete" silently did nothing (L-075) | shortcuts move to a reference-counted model |
| D-034 | Launcher tiles are per **window** (HWND+PID), enumerated off-thread, sorted stably | Users expect one icon per open window and to switch an older window; per-process counts cannot express that (L-076). Enumeration stays off the GUI thread (L-070) | a native event-driven window tracker exists |
| D-035 | Custom baud commits once on Enter/focus-out/list selection, and popup keystrokes are forwarded to the editor | Applying per keystroke reconfigured the driver 7 times per entry and the popup swallowed typing (L-077) | an editable combo gains native in-place editing |
| D-036 | Keep-awake lives in `omnicom/power.py` (one OS call), is owned by the GUI thread and released in `closeEvent` | `SetThreadExecutionState` is thread-scoped, so the request must be made and cleared by the same thread; isolating it keeps the toggle testable without touching real power state (R-062/L-078) | Windows exposes a per-process API |
| D-037 | Launcher tiles are painted `QWidget`s with a pinned 11 px caption that wraps and grows the tile | A fixed-size `QPushButton` clipped the caption; measuring with the same font used for painting is what keeps the wrap height correct (L-079) | a virtualised icon grid is introduced |
| D-038 | Two launcher areas: shortcuts spawn, running windows switch; per-window aliases keyed by `pid:hwnd` plus an `alias_pool` for restarts | Users describe instance identity ("A and B"), while the OS only gives titles; the pool restores aliases after a restart in stable order (R-063/L-079/L-080) | the OS exposes persistent window ids |
| D-039 | Ordering is model-owned: `apps` order plus per-app `window_order`, applied on rebuild | Drag must not depend on widget creation order, otherwise a background refresh reshuffles tiles. Nearest-centre drop keeps one code path for both areas (R-064/L-081) | the grid becomes a custom list view |
| D-040 | Shortcut removal edits config only; window removal sends WM_CLOSE to that HWND (PID-verified) | Conflating them either killed processes when the user tidied the list, or offered no way to close one window. Graceful close also lets an editor prompt to save (R-065/L-082) | a force-kill option is requested |
| D-041 | Capture writes RX and TX into one raw file, reports per-direction counts, and `clear()` truncates the open append handle | A raw stream stays byte-exact and cheap; labelling bytes would corrupt binary payloads, so direction is surfaced in the UI instead. O_APPEND means truncation alone restarts the file without reopening (R-066/L-084) | a labelled/text capture format is requested |
| D-042 | Both side columns share one width rule **and** one 280 px minimum; the centre stack gets an explicit 400 px minimum | A 1243 px `QStackedWidget.minimumSizeHint()` plus unequal pane minimums made any symmetric default collapse into 280/868/260 (L-086). Equal minimums keep the pair symmetric even when squeezed | the centre pane becomes collapsible |
| D-043 | Version 1.1.0 lives only in `omnicom/__init__.py`; docs are regenerated from `docs.py` | One source keeps the title, About dialog, CLI and READMEs consistent (R-069) | a changelog file is introduced |
| D-044 | The capture hint prints only the file size, polled every 500 ms while active | Users read progress as "how big is my file", not as two direction counters (R-066/L-088); polling a counter costs nothing compared with writing the bytes, and it keeps recording on the worker path untouched | per-direction progress becomes a requirement |
| D-045 | One `_log_line()` in the window owns "write a line + update live search"; `LogView.append_line()` returns the block and `compose_line()` yields exactly the inserted text | Two parallel paths (append vs. append+match) meant TX silently lost its live hits, and the duplicated rendering logic made live rows look different from history rows (L-089) | a structured log model replaces the text document |
| D-046 | The capture folder is a `paths` override validated by create+write-probe; the recorder switches folder for the *next* file only | Writing into a wrong folder would lose captures silently, and swapping the file leaves the old one truncated mid-session (R-070/L-090) | captures move to a database |
| D-047 | Accent is a mutable token family (`theme.set_accent`) re-applied with `app.setStyleSheet()` + one repaint sweep; wallpaper is a cached pixmap painted by `Aurora` | Local widget stylesheets only use neutral tokens, so a token swap covers the UI without rebuilding the window; the wallpaper needs the veil + status plate to stay readable (R-071, revises R-020 for an explicit user choice) | per-widget colours stop being neutral |
| D-048 | Clearing the log resets the counters through `PortManager.reset_stats()`; the title bar is zeroed immediately | The counters are the user's only evidence that nothing was dropped (R-017), so "clear" must not leave stale totals that look like current traffic (R-073/L-094) | counters become per-session instead of per-run |
| D-049 | Two file buttons (pick / send) plus a dedicated `txprint` event that reuses `_log_line()` | One button conflated "choose" with "transmit", and file bytes never reached the GUI so the log looked empty. A separate event keeps the `tx` counter from double printing while giving the log exactly the same rendering path as a typed send (R-074/L-095) | the file transfer moves off the shared send queue |
| D-050 | `logo.png` is the canonical mark; every icon asset is generated from it by `tools/make_brand_logo.py` → `make_logo.py` / `make_plugin_icon.py` | Three hand-drawn variants drifted apart, and a code-drawn mark cannot be used as an app icon. Rendering the widget geometry once gives one source for the window icon, title-bar bitmap and plugin tab (R-075/L-096) | designers deliver a designed logo file |
| D-051 | Hide the console only when this process is the sole client of it (`GetConsoleProcessList` <= 1); `--keep-console` opts out | A terminal that hosts a shell must keep its window, and a double-clicked launch should not leave a black box behind (R-076/L-097) | a frozen exe is ever built as a console app again |
| D-052 | Panes sample a cached, heavily blurred, lightly veiled wallpaper layer at their own window coordinates and wash it with `GLASS_ALPHA` | Real backdrop blur per widget is expensive and would drift from the page; one shared layer keeps the panes aligned with the photo, stays cheap (two smooth scales per window size) and lets `glass_floor()` prove the worst-case contrast (R-077/L-098) | a shader-based backdrop filter becomes available |
| D-053 | Tooltips are driven by a 100 ms poll of the widget under the cursor, not an application-wide event filter | The filter cost 4x on a 200-row group toggle (L-102) because Python sees every Qt event; polling costs a few microseconds per tick, ignores the platform timer that a mouse jiggle resets, and measures the delay with `time.monotonic()` (R-080/L-101) | Qt exposes a per-widget hover delay |
| D-054 | Records folder = the configured folder; only a *running* capture pins the old one for 打开目录 | After changing the folder the user must see and open the new one, but a file already being written keeps its location (R-078/L-099) | captures can move mid-file |
| D-055 | The log budget is a **text size** (MB, default 100, max 500) enforced by our own one-shot trimmer, with Qt's block limit kept only as a 2 M safety net | Users think in megabytes and want the newest lines kept; Qt's own block trimming costs 2-6 s on a large document while a single cursor removal of the same range costs ~0.2 s (R-081/L-104/L-105) | a streaming ring buffer replaces QPlainTextEdit |
| D-056 | Trimming drops to 85 % of the budget in one operation, and the dropped count lives in `LogView.trimmed` | Trimming on every append would cost ~50 ms per line; hysteresis makes it rare. One owner for the number means the badge can never disagree with the log (R-081) | per-line accounting becomes free |
| D-057 | The status strip is a `GlassStrip` sharing `paint_glass()` with the panes, and it paints **nothing** on the flat theme | The old stylesheet plate was opaque by construction, so it read as a white bar over the photo. Sharing the painter keeps the strip and the panes identical, and transparent-when-flat preserves R-020 (R-082/L-107) | the strip becomes part of the window frame |
| D-058 | Distribution is a zipapp (`dist/OmniCOM/OmniCOM.pyz` + `.cmd`), never a self-built exe; `paths.app_dir()/archive_dir()` resolve resources and data beside the archive | Endpoint security blocks unsigned self-extracting bootloaders, not the Microsoft-signed interpreter, so shipping no new binary is the only reliable route; code signing or an IT allowlist are the alternatives, both documented in `build.py` (R-083/L-108/L-109) | a signing certificate becomes available |
| D-059 | Tooltips are painted by our own translucent `TipPopup`, and Qt's native tooltip is suppressed with a `QHelpEvent` filter | A ``QToolTip`` window is rectangular, so ``border-radius`` only rounds the inside and the platform's white shows at the corners; owning the widget removes that block and lets the card be glass like the panes (R-084/L-110/L-112) | Qt exposes a chrome-less tooltip hook |
| D-060 | The caption row paints nothing at all; readability comes from the primary ink plus a white glyph halo | The user asked for "no frame and no colour" (R-082). With no plate the text can land on the darkest page, where only ``INK`` passes 4.5:1 (grey 2.49:1, amber 1.70:1), and the halo - a property of the glyphs - covers the photo case without reintroducing a box (L-111) | a plate becomes acceptable again |
| D-061 | The release package is a folder with the official CPython *embeddable* runtime, a trimmed PySide6 set and `OmniCOM.pyz`; launchers call `runtime\pythonw.exe` | The user asked for a package that installs nothing; a self-extracting single binary is the shape endpoint tooling objects to and unpacks hundreds of MB per launch, while a bundled signed interpreter plus a `_pth`-pinned site-packages folder is dependency-free, relocatable and reproducible (R-083/L-114) | a signed installer becomes available |
| D-062 | Only the Qt modules the app actually imports are shipped (Quick/QML/Designer/3D/WebEngine/Multimedia/Charts/… excluded), and the build ends with the packaged `--selftest` | Trimming takes the payload from 171.5 MB to 77 MB, and running the selftest *inside* the bundle turns a missing module into a build failure instead of a user-facing crash (R-083) | a Qt module gets used at runtime |
| D-063 | Both test harnesses point `OMNICOM_DATA_DIR` at their own wiped folder under `.artifacts/test-data/`, and the perf step closes the DEMO link while it measures exact counts | A suite that writes into the real `omnicom-data/` both destroys the user's command library and stops being repeatable: after a few runs the capture folder held 353 files and the block/line assertions started depending on telemetry timing (L-116) | data folder preferences become testable on their own |
| D-064 | Window show/hide is animated by our own QPropertyAnimation group, and the taskbar's SC_MINIMIZE is intercepted in `nativeEvent` so the fade can finish before the window hides | A translucent frameless window gets no DWM minimize transition, so both the taskbar and our own button looked like a hard cut; intercepting the message is the only way to animate *before* Qt hides the window, and it keeps one code path for every minimize source (L-117) | native frameless tool windows are dropped |
| D-065 | The distribution documents itself: the same entry point accepts a `cli` subcommand and the bundle ships `CLI.md` + `AI-GUIDE.md`; the project is MIT-licensed | An agent given only the unzipped folder had no way to learn the JSON contract, and a tool nobody can legally reuse is not really shippable; both are one-file facts, so they travel with the package rather than living in the repository only (R-086/L-118) | the CLI contract grows past one document |
