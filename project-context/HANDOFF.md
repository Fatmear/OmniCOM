## Implemented

- 修复已独立复现的致命错误：`drawnBuffer` 曾与历史数组别名，追加时一边遍历一边向同一数组 push，导致无限增长 / `RangeError`。现在按通道版本缓存独立绘图切片。
- Python 用绝对接收序号、确认后提交游标、永不复用批次编号；满 deque 时继续收数不会吞掉尚未发送的尾部，迟到 ack 不能释放新批次。纯 value/gauge/bar/lamp 看板也能持续刷新。
- 两端 `points=0` 都严格最多保留5000点；绘图窗口独立，默认300。增量提取不再先复制整个 deque。
- 曲线实时仅更新 series id/data；仪表仅更新数值，结构不重复创建；关闭滑块数据阴影。保留 LTTB、固定 progressive=800，不重试 L-312 已回退方案。
- 最多一个在途批次。等待实际 rendered/finished 事件，而非 setOption 返回；rendered 后用可被后续绘制重置的 rAF 屏障确认。只等 finished 已真实复现卡住。Python 保留1.5秒超时和切页重同步。
- 确认驱动下一批，只补齐从上次发送起算的目标节拍；不再绘制完成后重复等待完整轮询间隔。保留定时器作空闲唤醒与超时恢复。
- 布局统一为40ms合并任务；去掉递归 extent、重复 settle 和三次延后居中。显式 autoPlaced 防覆盖用户坐标。视口外卡按需初始化/追帧，尺寸未变不 resize。
- R-311 配置往返保留 channels/decimals/状态文字及布局；拒绝非有限范围和重复ID，非法导入不改变当前布局。

## Open Boundaries

- R-320 性能目标尚未完整验收：最重负载仍约5批/秒、完成P95约249ms；不是稳定30fps。
- 负载直接 feed，不是长期真实串口；斜线不是噪声/复杂波形。24卡测试有视口外懒绘制，不代表24张同时可见。
- 负载交互探针是 JS 往返/滚动、添加卡片与构建菜单，不是负载下的真实鼠标拖动/菜单点击。现有功能回归有 pointer 序列，但不能替代组合负载实测。
- rendered+rAF 屏障确认了实际绘制事件，不是浏览器合成器/显示器呈现时间；隐藏页 rAF 暂停靠超时和返回页面重同步恢复。
- 停顿采样仅落在 `app.processEvents()`，未定位 Qt 内部具体工作；未证明写盘是根因，不引入猜测性的异步存储层。
- 本轮没有重跑全工程 GUI / 总验收；旧记录仍有 R-055/R-001 失败及 R-306 未覆盖，不能声称全工程全绿。
- 历史日志回放仍受live5000点容量限制；旧版看板需求定义/验收注册仍有缺口，命令并发合并、文件模式CLI旁路、HEX大文件内存/撤销等旧边界未在本轮处理。
