# 产品范围（这个产品要实现什么）

Updated: 2026-11-25

这份文件定义 **OmniCOM 要成为什么**，与 `CAPABILITIES.md`（今天做到什么程度）严格区分：

- **本文件 = 目标范围（scope）**：产品承诺支持哪些功能、刻意不支持哪些、每个功能的验收标准。
  它是“要做什么”的权威来源，变化时先改这里。
- `CAPABILITIES.md` = 实现现状（working / partial / broken / planned / retired）。
- `REQUIREMENTS.md` = 具体约束条款（每条规则一个 `R-` 编号）。

一个功能先在这里立项（有目标与判据），再由 `CAPABILITIES.md` 报告它到了哪一步。
**没有在本文件出现的用户功能，不应被悄悄加入；要加入就先在这里登记。**

---

## 一句话定位

**嵌入式串口调试工作台：一个窗口替代串口助手、终端、传输工具与脚本接口。**

目标用户是调试 MCU / 模组 / 板卡的工程师：需要一边看日志、一边发命令、一边传固件，
并且希望脚本与 AI 也能操作同一套能力。

## 解决的四个用户问题

| # | 用户问题 | 产品承诺 |
| --- | --- | --- |
| P1 | 串口日志看不全、留不住，丢字没人知道 | 每行带毫秒时间戳与方向；不可见字符可见；按字节预算缓冲；**任何丢弃都计数并显示**，绝不静默丢字节 |
| P2 | 命令是一次性输入，重复调试靠手打 | 可分组、可备注、可定时/延时/HEX 的命令库；整组依次发送；导入导出；粘贴多行自动拆分 |
| P3 | 传固件要换工具 | 内置 XMODEM / YMODEM / ZMODEM；普通文件发送带进度与速率；接收文件自动落盘 |
| P4 | 脚本与 AI 无法操作图形工具 | 同一入口提供 CLI：一次调用一个 JSON 文档，退出码等于 `ok`；窗口占用串口时 CLI 通过窗口代理，不抢端口 |

## 功能范围（scope）

标记：**CORE** = 产品必须提供；**OPT** = 可选/插件化；**OUT** = 明确不做。

## 明确不做（OUT）

这些功能**不会实现**。用户明确否决或与产品定位冲突，所以从范围里排除。
如果哪天要做，先在「范围变更记录」写一行，再从本表移走。

| 编号 | 不做 | 原因 |
| --- | --- | --- |
| O-1 | 不做网页版 / 本地 HTTP 服务 / 浏览器外壳 | 用户要的是原生 Python 桌面窗口（R-018） |
| O-2 | 不发布自编译 `.exe` | 公司安全策略拦截运行（R-019） |
| O-3 | 不做看板的“开关型”卡片与编辑态 | 用户明确「控件不需要开关，界面不需要编辑」（R-173） |
| O-4 | 商店插件不随发布包分发 | 避免更新覆盖用户已装/已改的插件（R-174） |
| O-5 | 不记录栏/发送栏开关的上次状态 | 开关一律从默认值开始（R-155） |
| O-6 | 不做日志行距设置 | `QPlainTextEdit` 不支持，只能改用 `QTextEdit`（L-140） |

## 范围与现状的关系

`CAPABILITIES.md` 里每个 `partial` / `broken` / `planned` 行，都应能对应到上面某个 `S-x.y`：

- `partial` / `broken` → 已立项、未达标
- `planned` → 已立项（出现在本文件），尚未开工

如果 `CAPABILITIES.md` 出现一个在本文件找不到对应 `S-` 编号的功能，说明范围没登记，
应先在本文补一条，再继续开发。

## 变更规则

1. **用户说“要做这个功能” → 当场在本文加一条 `S-x.y`**，写清功能与验收判据。
   不许先写代码、回头再说；没登记的功能等于没同意。
2. **用户说“不要了 / 去掉这个” → 当场把它从上面的范围表里删掉**，
   并在下面的「范围变更记录」加一行，写清删了什么、为什么、谁的哪句话。
   范围表要保持干净可读，删除痕迹留在变更记录里，不要堆在范围表里。
3. 删除时同步检查：`CAPABILITIES.md` 对应行改成 `retired`（或直接删），
   `REQUIREMENTS.md` 里相关规则标 `superseded` / 移入归档，相关测试一并处理。
4. 每个新增功能必须写出验收判据，否则它只是想法，不是范围。
5. 与 `REQUIREMENTS.md` 冲突时：本文件定“做什么”，`REQUIREMENTS.md` 定“必须怎样做”，
   两者冲突要当场向用户确认哪一条优先。
6. 变更记录只追加，不删改。它是唯一允许保留“已经不要的功能”的地方。
